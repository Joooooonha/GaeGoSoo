# Mission 2 — 환경변수 때문에 서비스가 다르게 동작한다

**Level**: 1
**날짜**: 2026-09-11
**환경**: `gaegosoo` EC2, `ops-lab`

## 한 일

1. 환경변수 없이 `java -jar app.jar` 실행 → `curl localhost:8080/health` → `OK`
2. 프로세스 종료 → `export SERVER_PORT=9090` → 재실행
3. `curl localhost:8080/health` → 실패 (더 이상 그 포트에서 안 뜸)
4. `curl localhost:9090/health` → `OK`

## 개념 정리 (Q&A로 다진 부분)

- 환경변수는 프로그램이 스스로 `getenv()`류 API로 읽어가는 것 — 누가 강제 주입하는 게 아님.
- 목적: 코드/빌드 산출물은 그대로 두고, 실행 환경에 따라 동작을 다르게 하기 위함 (같은 jar가 개발/운영에서 다른 DB_URL, PORT 등을 쓸 수 있게).
- 부모→자식으로 딱 한 방향, 딱 **생성 시점의 스냅샷**으로만 상속됨. 자식은 이후 자기 복사본을 자유롭게 바꿔도 부모에게 영향 없음.
- `export`는 "이 변수를 자식에게도 보이게 내보낸다"는 표시. `export` 안 하면 그 셸 자신만 쓸 수 있음.
- 이미 실행 중인 프로세스는 부모가 나중에 `export`해도 영향 안 받음 — 그래서 "kill → export → 재실행" 순서가 중요했음.
- 새 SSH 세션(새 터미널 탭에서 `ssh gaegosoo`)은 기존 세션의 자식이 아니라 완전히 별개의 로그인이라 환경변수가 전혀 공유되지 않음.

## One-line takeaway

환경변수는 프로세스가 생성되는 순간 부모로부터 스냅샷으로 복사되며, 이후 부모가 값을 바꿔도 이미 떠 있는 자식에게는 반영되지 않는다 — 그래서 실행 중인 서비스의 설정을 바꾸려면 "값을 바꾸고 → 프로세스를 다시 띄우는" 과정이 필요하다.
